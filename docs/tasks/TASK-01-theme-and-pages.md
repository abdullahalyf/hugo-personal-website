# TASK-01 — Own Hugo theme, all pages, `harbor` style, dark mode, CI + Vercel

Builder: Puku (local, Windows). Branch: `task/01-theme`. Report: `docs/reports/TASK-01-report.md`.
First read `AGENTS.md`, `docs/DESIGN.md`, `personal/profile.yaml`. They are binding.
Use your frontend-design / verification skills if you have them; no AI-slop patterns
(see DESIGN.md §1).

## Goal
A complete, professional personal site rendered 100% from `personal/profile.yaml`, in the
`harbor` style, light + dark, ready to deploy on Vercel. The other 4 styles come in
TASK-02, but build the CSS architecture for them now (tokens + per-style file).

## Build
1. **Project skeleton**
   - `hugo.toml`: `baseURL = "/"`, `relativeURLs = false`, `theme = "folio"`,
     `[params] style = "harbor"`, `description`, `[markup.goldmark.renderer] unsafe = false`,
     menus for Home / About / Projects / Blog / Contact, `enableRobotsTXT = true`,
     sitemap on, taxonomies off except none needed.
   - `.hugo-version` with the latest stable Hugo extended version (check releases).
   - `content/_index.md`, `content/about.md`, `content/projects.md`, `content/contact.md`
     (front matter only, layouts pull data), `content/blog/_index.md`,
     `content/blog/hello-world.md` (one real-looking example post, ~250 words, with a
     heading, list, quote, image and code block so prose styles are visible).
   - **`personal/` folder = the only thing a friend replaces** (see `personal/README.md`).
     In `hugo.toml` add `[[module.mounts]]`: `personal/profile.yaml` → `data/profile.yaml`,
     `personal/photos` → `assets/photos`, `personal/cv.pdf` → `static/cv.pdf`
     (plus the default mounts for content/static/assets/layouts so nothing else breaks).
   - Demo files with the FIXED names: `personal/photos/profile.jpg`, `project-1.jpg`,
     `project-2.jpg`, `hobby-1.jpg`, `personal/cv.pdf` (1-page). Placeholders must look
     intentional: solid style-neutral tone + initials or a simple shape, NOT stock photos
     of people. Keep each image < 150 KB.
   - Image lookup by fixed base name, any extension:
     `resources.GetMatch "photos/project-1.*"` (`.jpg .jpeg .png .webp`). Project N ↔
     Nth item in `projects`, hobby N ↔ Nth item in `hobbies`. Missing file → no image,
     no error. CV button shows if `cv_url` is set or `personal/cv.pdf` exists, else hidden.
   - Replacement test: overwrite `profile.jpg` with a `.png` of the same base name
     (delete the .jpg) → build still works and shows the new photo.
2. **Theme `themes/folio/`**
   - `layouts/_default/baseof.html` (skip-link, header, main, footer), `index.html`,
     `about` / `projects` / `contact` single layouts, `blog` list + single, `404.html`.
   - Partials: `head.html` (meta, OG, JSON-LD Person, preload font, no-flash theme
     script), `header.html`, `footer.html`, `hero.html` (switch on layout:
     split|centered|typographic|sidebar|band — implement all 5 structurally now, style
     them fully only for split; others just must not break), `timeline.html`,
     `project.html`, `skills.html`, `socials.html`, `icon.html` (inline SVGs),
     `img.html` (processing helper → WebP, srcset 2 sizes, width/height).
   - **Validation partial** `validate.html` called once per build: `errorf` with a clear
     message if a required field (`name, role, now, photo, bio, contact.email`) is
     missing, or no `personal/photos/profile.*` file exists. Message must say which file
     to add, e.g. "Add your photo as personal/photos/profile.jpg".
   - CSS in `assets/css/`: `base.css` (reset, tokens usage, layout, components),
     `styles/harbor.css` (tokens light+dark). Pipe: concat base + chosen style →
     minify → fingerprint. No Tailwind, no SCSS required.
   - `assets/js/theme.js`: dark toggle + mobile menu, vanilla, < 3 KB min.
   - Favicon: SVG from initials in accent colour, generated by template.
3. **Deploy + CI**
   - `vercel.json`: build `hugo --gc --minify`, output `public`, env `HUGO_VERSION`
     equal to `.hugo-version`. (Vercel framework preset "Hugo".)
   - `.github/workflows/ci.yml`: on PR + push to main → install pinned Hugo extended →
     `hugo --gc --minify --panicOnWarning` → run `htmltest` or `lychee` for internal
     links only. Must pass.
   - `.gitignore`: `public/`, `resources/_gen/`, `.hugo_build.lock`.

## Demo content — complete A to Z (added by orchestrator)
The repo must ship as a **finished-looking demo site**. A friend only replaces files in
`personal/` (same names) and the blog posts; no agent work needed later. So every section
is filled, every image exists, every page looks real.

1. **`personal/profile.yaml`** — expand the fictional demo person so EVERY section is
   used: 2 education, 2 experience, 4 skill groups, 4 projects (2 featured, all with
   images), 3 achievements, 3 languages, 2 hobbies (with images), 5 socials, phone, CV.
   Specific, believable, plain English. No buzzwords, no "passionate about".
2. **Demo images — must NOT look AI-generated or cheap** (no glossy 3D blobs, no
   purple gradients, no fake hands/faces, no AI art):
   - `profile.jpg`: a clean, neutral illustrated portrait placeholder (flat, two-tone,
     head-and-shoulders silhouette on a soft background), 1000×1250, made by you as
     SVG → JPG. No real person's face.
   - `project-1..4.jpg`: **real screenshots** of small, believable mock app UIs that you
     build as throwaway HTML (dashboard, mobile app list, landing page, bot chat) and
     capture at 1600×1000 with a headless browser. Keep the throwaway HTML in
     `tools/mockups/` so they can be regenerated.
   - `hobby-1..2.jpg`: free-licence photos (Unsplash/Pexels, landscape/travel/objects,
     no identifiable people) — record source URL + photographer in `personal/CREDITS.md`.
     If you can't download, make a tasteful flat illustration instead.
   - Blog cover images: same rules (screenshot, illustration or free-licence photo).
   - All images compressed (< 200 KB each), correct aspect ratio, no text baked in.
3. **`personal/cv.pdf`** — a real-looking 1-page CV of the demo person (clean
   typography, matches profile.yaml), generated from HTML → PDF. Keep source in
   `tools/cv/`.
4. **Blog** — 3 demo posts in `content/blog/` (300–600 words each), written like a real
   CSE student would: e.g. "What I learned building my first Laravel app",
   "My semester study system", "A trip to Sajek Valley". Each with front matter
   (title, date, summary, cover image, tags), headings, a list, one image, and one code
   block or quote. Human, specific, no filler intros ("In today's fast-paced world…").
   Add `content/blog/README.md` (not rendered) explaining how to add/delete a post.
5. **Every page** must look complete with the demo: no lorem ipsum, no "TODO", no empty
   areas, no broken image.

Check: screenshot every page (light + dark, mobile + desktop) and look at them yourself;
fix anything that looks templated or empty before writing the report.
